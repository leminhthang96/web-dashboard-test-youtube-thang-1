This Next.js application uses a single-root npm workspace with `package.json` and a committed `package-lock.json` lockfile. There is no monorepo tooling (no `pnpm-workspace.yaml`, no Turborepo, no Nx); all dependencies — runtime, dev, and shadcn/ui primitives — are declared in one flat dependency list.

**Package manager and lockfile**
- Manager: npm (default for the project). The presence of `package-lock.json` at the repo root pins every transitive dependency to an exact version, ensuring reproducible installs across environments.
- Lockfile: `package-lock.json` is committed alongside `package.json`, so CI and local dev resolve from the same snapshot rather than re-resolving semver ranges.
- No vendoring or private registry overrides are configured; all packages resolve against the public npm registry.

**shadcn/ui integration**
- The project integrates shadcn/ui via the `@shadcn/react` CLI and its configuration file `components.json`. This configures style (`new-york`), Tailwind setup, path aliases (`@/components/ui`, `@/lib/utils`, etc.), and the icon library (`lucide`). Shadcn components are copied into `src/components/ui/` as source files rather than consumed as a published package, making them part of the app's own dependency surface.

**Dependency categories**
- Runtime deps include the Next.js framework, React 19, Firebase client/admin SDKs, Radix UI primitives, shadcn/ui, TanStack Table, Recharts, Zod, Zustand, date-fns, lucide-react icons, and theme utilities (`next-themes`, `tailwind-merge`).
- Dev deps cover TypeScript, ESLint (`eslint-config-next`), Tailwind CSS v4, PostCSS, and type definitions for Node and React.

**Conventions and constraints**
- All third-party libraries are pinned via caret ranges in `package.json` but locked by `package-lock.json`; upgrades should be performed through `npm update` / `npm install` and the resulting lockfile committed.
- No `overrides`, `resolutions`, or custom `.npmrc` registries are present, so there is no strategy for pinning transitive versions or routing to a private registry.
- The `.gitignore` excludes `node_modules` and PnP/Yarn artifacts, while `.gitattributes` and `.prettierignore` contain legacy entries for `yarn.lock` and `pnpm-lock.yaml` that are not used here.
