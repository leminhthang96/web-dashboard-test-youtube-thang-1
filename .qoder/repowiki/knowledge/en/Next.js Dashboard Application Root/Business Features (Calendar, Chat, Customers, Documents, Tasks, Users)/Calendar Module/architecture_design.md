The module follows a clear three-layer split under `src/modules/calendar/`:
- `components/` — presentational React components (`calendar-main.tsx`, `calendar-unified.tsx`, `calendar-sidebar.tsx`, `event-form.tsx`, `date-picker.tsx`, `quick-actions.tsx`, `calendars.tsx`, `calendar.tsx`). Components are client-side (`"use client"`) and consume UI primitives from `@/components/ui/*` (shadcn). Two entry variants exist: `calendar-main.tsx` (self-contained grid + list view) and `calendar-unified.tsx` (sidebar + sheet layout).
- `hooks/use-calendar.ts` — a single React hook encapsulating local state for selected date, event form visibility, editing context, and stubbed CRUD handlers; it exposes a typed `UseCalendarReturn` interface.
- `services/` — data layer with `types/calendar-types.ts` defining the shared `CalendarEvent` and `Calendar` interfaces, `calendar-mock-data.ts` that loads `data/*.json` and normalizes dates into current month/year, and `calendar-services.ts` which wraps those mocks through `getFirestoreCollection` / `getFirestoreDocumentCollection` adapters plus a `normalizeDate` helper supporting Date, string, Firestore timestamp, and `{toDate}` objects. Dependency direction is one-way: components → hooks → services → JSON/Firestore adapter.

No build manifest exists in this scope; the module is consumed as an importable package within the Next.js app.
