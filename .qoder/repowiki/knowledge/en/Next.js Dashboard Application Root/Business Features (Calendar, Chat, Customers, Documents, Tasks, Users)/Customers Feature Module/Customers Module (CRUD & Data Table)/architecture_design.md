Two-layer layout under `src/modules/customers/`:
- `components/`: a reusable `DataTable<TData,TValue>` client component (`data-table.tsx`) that wires `@tanstack/react-table` state (sorting, filtering, pagination, visibility) and delegates rendering to shadcn/ui `<Table>` primitives; it composes smaller presentational pieces — `data-table-toolbar`, `data-table-pagination`, `data-table-row-actions`, `data-table-view-options`, `data-table-column-header`, plus an `add-customer-modal`. Columns are defined in `columns.tsx`.
- `services/`: a thin data layer (`customer-services.ts`) exposing `getCustomers`, `createCustomer`, `updateCustomer`, `deleteCustomer`, `seedCustomersWithClient`, and `getCustomerStats`. All mutations go through Firebase Firestore (`collection(db, "customers")`) and enforce Row-Level Security by attaching the current user's UID via `getCurrentUserId()` (which wraps `onAuthStateChanged` once and caches the promise). The `Customer` type is derived from a Zod schema in `types/customer-types.ts`; mock seed data lives in `customer-mock-data.ts`.

Dependency direction: components import only the `Customer` type from `services/types`; they never call Firestore directly. The services depend on `@/lib/firebase/client` for `auth`/`db` and own all auth/session handling. No server-side code or API routes live inside this module.
