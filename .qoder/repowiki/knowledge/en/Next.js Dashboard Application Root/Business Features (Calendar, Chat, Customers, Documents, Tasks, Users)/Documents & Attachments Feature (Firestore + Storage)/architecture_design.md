Two-layer layout inside the module:
- `services/` is the persistence boundary. `document-services.ts` wraps the Firestore `documents` collection (CRUD + soft-delete via `deletedAt`) and depends only on `@/lib/firebase/client`. `document-file-services.ts` handles the parallel upload pipeline to `documents/{docId}/attachments/{fileName}` in Firebase Storage plus metadata writes to the `attachments` subcollection; it exposes an `UploadProgress` callback contract so UI can drive per-file progress bars. `folder-services.ts` manages the `folders` collection with parent-child relationships and enforces empty-folder-only deletion.
- `components/` is purely presentational/stateful React: a generic `DataTable<TData>` built on `@tanstack/react-table` with pluggable columns, toolbar, pagination, row actions, and view options; `AddDocumentModal` orchestrates a two-step flow (create document → optional file upload) and delegates side effects to callbacks (`onAddDocument`, `onFilesUploaded`) rather than calling services directly.
- Shared contracts live in `services/types/document-types.ts` (Zod schemas for `Document`, `DocumentAttachment`, form data, plus extension allow/block lists and size limits). Components import these types but never call services — they receive async handlers as props, keeping the component layer testable without Firebase.
