Each child under `src/modules/<feature>/` follows the same internal layout — `components/` for shadcn/TanStack-based UI, `services/types/<feature>-types.ts` for shared domain types, `services/*-mock-data.ts` for seed data, and `services/*-services.ts` as the live backend adapter over Firebase Firestore. There is no cross-feature orchestration layer; features are wired into the app shell via lazy-loaded routes and communicate only through the global Zustand store or direct imports from `src/lib/firebase`. The consistent `types + mock-data + services` triad lets every feature swap its backend without touching components, and features like documents and users additionally expose sub-services (e.g. `document-file-services.ts`, `user-role-services.ts`) for secondary concerns such as Storage uploads and role assignments.
