The module is split into two layers:
- `components/` — React client components built on `@tanstack/react-table`. `data-table.tsx` is the composition root that wires sorting, filtering, faceted search, pagination, row selection and delegates UI to sibling primitives (`data-table-toolbar`, `data-table-column-header`, `data-table-faceted-filter`, `data-table-pagination`, `data-table-row-actions`, `data-table-view-options`). Column definitions live in `columns.tsx` via a `getTaskColumns()` factory so action callbacks can be injected.
- `services/` — thin persistence layer over Firebase Firestore (`task-services.ts`) exposing `getTasks`, `createTask`, `updateTask`, `deleteTask`, `seedTasksWithClient`, plus a pure `getTaskStats` helper. Shared shape is declared once in `services/types/task-types.ts` using a Zod schema (`taskSchema`) inferred as the `Task` type; both services and components import this single source of truth.

Dependency direction: components → services/types → services/*; services depend only on `@/lib/firebase/client` and never on components. `task-chart-services.ts` and `task-statistics-services.ts` are reserved placeholders for future chart/stat logic. The feature has no server entry point — it is consumed from a parent page that supplies data/state and forwards mutation callbacks through `DataTable` props.
