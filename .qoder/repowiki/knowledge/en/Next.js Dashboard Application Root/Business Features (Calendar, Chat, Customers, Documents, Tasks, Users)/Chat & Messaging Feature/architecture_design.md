The module is split into two layers:
- `services/` owns all state and data. `types/chat-types.ts` declares the shared `User`, `Message`, `Conversation` interfaces. `chat-mock-data.ts` re-exports three JSON fixtures (`conversations.json`, `messages.json`, `users.json`) typed via `as`. `chat-services.ts` defines a single Zustand store (`useChat`) with actions for conversations, messages, users, selection, search, typing, and online presence; it also exposes `getChatData()` which loads the three collections through `getFirestoreCollection` from `@/lib/firebase/firestore-query`, flattening per-conversation messages into a `Record<string, Message[]>` shape.
- `components/` are pure presentational React components (`chat.tsx` as the root layout orchestrating sidebar/message area, `conversation-list.tsx`, `message-list.tsx`, `message-input.tsx`, `chat-header.tsx`). Components import only the `useChat` selector and the type exports — they never touch the JSON fixtures or Firestore directly.

Dependency direction: components → `useChat` store → `chat-mock-data` → JSON fixtures. The store is the single source of truth; the parent component hydrates it once on mount and auto-selects the first conversation.
