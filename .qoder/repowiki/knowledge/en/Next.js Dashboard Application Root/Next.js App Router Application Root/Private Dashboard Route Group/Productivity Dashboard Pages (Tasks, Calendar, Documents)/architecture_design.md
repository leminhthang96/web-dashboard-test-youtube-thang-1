Three sibling route segments under src/app/(private)/ — tasks/page.tsx, calendar/page.tsx, documents/page.tsx — each acting as a thin page-level orchestrator for one productivity feature:
- tasks/ and documents/ are "use client" React components that own local useState for their entity lists (plus an attachments map for documents), fetch via get* from @/modules/<feature>/services/*, mutate through create*/update/delete* service functions, and render a DataTable whose column definitions come from getXxxColumns(...).
- calendar/ is a server component (export default async function) that calls getCalendarData() at render time and passes plain events / eventDates props down to @/modules/calendar/components/calendar.
- Dependency direction is strictly inward: these pages import only @/modules/<feature>/components/*, @/modules/<feature>/services/*, and @/modules/<feature>/services/types/*; they never import each other or reach into @/components/ui/* beyond the shared Card primitives. The (private) route group provides the authenticated layout shell; the pages themselves contain no auth logic.
