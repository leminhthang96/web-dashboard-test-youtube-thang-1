Each subdirectory (`account`, `appearance`, `connections`, `notifications`, `user`) is a Next.js Route Segment exporting a single default client component from its `page.tsx`. There is no shared layout or container — each page owns its own form schema, state, and data flow. Data persistence is split by concern: `account` and `notifications` call Firebase Auth helpers from `@/lib/firebase/auth` (`saveUserProfile`, `changePassword`, `deleteUserAccount`, `getUserNotifications`, `saveUserNotifications`) via `onAuthStateChanged(auth, ...)` to load per-user data; `appearance`, `connections`, and `user` are currently local-only UIs with `console.log` stubs for submission. All pages consume the shared shadcn/ui primitives (`Card`, `Form`, `FormField`, `Select`, `RadioGroup`, `Switch`, `Checkbox`, `Table`, etc.) from `@/components/ui/*` and use Sonner's `toast` / `toast.promise` for user feedback.
