Each sub-module follows an identical internal layout: `components/` holds presentational React components, while `services/` owns the data layer split into `data/*.json` fixtures, `types/` Zod schemas (when applicable), a `*-mock-data.ts` barrel re-exporting the JSON payloads, and a `*-services.ts` entry point that either returns mock data directly (`dashboard-2`, `settings`) or fans out parallel calls via `getFirestoreCollection` with a fallback payload (`dashboard-1`). Dependency direction is strictly one-way — components import only from the module's own `services/*`; cross-module imports are absent. `dashboard-1` additionally defines a per-module `zod` schema in `services/types/dashboard-types.ts` used to type its table rows, whereas `dashboard-2` and `settings` keep no local types (settings types live in `src/lib/firebase/auth.ts` as noted by comments). The three modules are peers under `src/modules/` with no shared orchestration file inside this scope.
